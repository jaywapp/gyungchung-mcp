## 요청

운영진이 AI(Claude 등)에게 말로 시켜서 경충FC 데이터를 기록·수정·삭제할 수 있게 관리자 MCP를 만든다. 설계부터 진행한다.

## 현재 상태와 근거

- `gyungchung-mcp`는 조회 전용 v1이다. 도구 11개가 `spec/mcp-tools-v1.json`에 정의되어 있고 `src/mcp/server.ts`가 운영자 권한에 맞는 도구만 등록한다.
- MCP 서버는 로그인한 운영자의 OAuth 토큰과 publishable key로 Supabase에 접근한다(`src/data/supabase.ts`). 서버 전용 키를 쓰지 않으므로 DB 권한 규칙이 그대로 적용된다.
- 호출 기록은 `private.mcp_audit_logs`에 남는다(`gyungchung` 레포 `apps/web/supabase/migrations/20260828120000_admin_mcp_read_api.sql`). 누가 어떤 도구를 호출했는지만 남고, 무엇이 어떻게 바뀌었는지는 남지 않는다.
- 웹 관리자 화면의 저장 경로는 두 종류다.
  - DB 함수 호출: 출석(`save_attendance_batch`), 팀 편성(`save_event_teams`, `save_event_team_mode`), 경기 기록(`save_event_game_operation`, `save_event_goals_only_stat`), 경기 확정(`finalize_event_game`), 우승팀(`save_event_winners`).
  - 표에 직접 쓰기: 일정·장소·일정별 용병(`components/admin-console.tsx` 225~281행), 회비 납부 상태(`lib/fee-payment.ts`, `admin-console.tsx` 213~222행), 월 회비 일괄 부과(`components/admin-bulk-fee-dialog.tsx`). 회비 금액 기준은 `packages/core`의 `fee-rules`에, 반복 일정 생성 규칙은 웹 화면 코드에 있다.
- 2026-09-09 검증 기록(`public-oauth-boundary-20260909.md`)에 따르면 운영 Supabase의 OAuth 서버는 켜졌지만 OAuth 클라이언트 자동 등록(DCR)은 꺼져 있다. 실제 계정 로그인, 토큰 발급, 권한별 조회 도구 실행은 검증된 적이 없다.

## 질문과 답변

| 질문 | 답변 (2026-11-16, 사용자) |
|---|---|
| 어떤 작업을 AI에게 시키고 싶은가 | 경기 일정 기록, 회비 납부 기록 등 |
| "경기 일정 기록"의 범위 | 일정 등록·수정·삭제와 당일 기록(출석, 용병, 팀 편성, 경기 스코어·득점·도움, 우승팀) 전부 |
| DB 저장 방식 | 모든 쓰기를 MCP 전용 DB 함수로 새로 만든다 |
| 변경 전 확인 절차 | 위험한 것만 미리보기. 한 건 등록·수정은 바로 저장하고, 삭제·여러 건 일괄 변경·경기 확정은 미리보기 후 승인 |

| 1차 설계안(일정·회비 전용 도구 15개)에 대한 의견 | DB에 있는 모든 데이터를 쉽게 처리하고 싶다 |
| 모든 데이터를 다루는 방식 | 범용 표 도구 + 맞물린 표는 전용 도구. 비밀 값이 있는 표는 제외 |
| 기존 조회용 MCP의 연결 확인 방법 | OAuth 클라이언트 자동 등록을 켠다 |
| 대상 AI 앱 | Claude와 ChatGPT 둘 다 쓸 수 있게 한다 |

## DB 표 현황 (마이그레이션 기준)

표는 약 110개다. `public` 약 30개, `private` 약 80개.

- 단순한 표 약 25개: 회원, 회비, 일정, 장소, 공지, 의견, 용병, 시즌 기록 등
- 맞물린 표 약 40개: 경기 기록, 팀 편성, 우승, 스카우터 평가 등. 버전·스냅샷·영수증 표가 함께 움직인다
- 비밀 값이 있거나 시스템이 관리하는 표 약 45개: 푸시 키, AI 키, 입금 계좌, 작업자 상태, 사용 통계, 감사 로그

## 가정 (사용자 미확인, 설계서에 "세션 판단"으로 표시)

- 범용 표 도구는 시스템 관리자만 쓴다. 직책 운영진은 자기 권한의 전용 도구와 v1 조회 도구만 쓴다.
- 표별 허용 범위의 초기 분류(설계 6장).
- 전용 DB 함수는 저장을 기존 DB 함수 호출로 처리하고, 권한 확인·변경 기록·중복 실행 방지를 감싼다.
- 출석 일괄 저장은 한 일정 안의 변경이라 미리보기 없이 저장한다.
- 변경 기록 보존 기간은 1년이다.
- Admin API(`/api/v1/admin/*`)의 쓰기 엔드포인트는 이번 범위에서 만들지 않는다.

## 범위

- 범용 표 도구: 표 목록, 표 설명, 행 조회, 행 추가, 행 수정, 행 삭제
- 표별 허용 목록과 민감 열 처리
- 전용 도구: 출석, 팀 편성, 경기 기록, 경기 확정, 우승 회원, 월 회비 일괄 부과
- 변경 기록과 그 조회 도구

## 비범위

- 임의 SQL 실행
- 비밀 값이 있는 표와 시스템이 관리하는 표의 조회·변경
- 직책 운영진의 범용 표 도구 사용
- 투표·설문·선거 저장, 환영 페이지, 계정 발급, 비밀번호 초기화, 권한·역할 변경 (다음 묶음)
- 웹·모바일 앱 코드 변경, 자동 되돌리기(undo)

## 완료 기준

- 시스템 관리자가 Claude에서 허용된 모든 표를 말로 조회·추가·수정·삭제할 수 있다.
- 시스템 관리자가 아닌 사람에게는 범용 도구가 보이지 않고, 직접 호출해도 거부된다.
- 허용 목록에 없는 표와 숨긴 열은 조회되지 않는다. 조회 전용 표에는 범용 쓰기가 거부된다.
- 삭제, 여러 행 변경, 경기 확정, 회비 일괄 부과는 미리보기를 거치지 않으면 저장되지 않는다.
- 같은 요청을 두 번 보내도 한 번만 반영된다.
- 성공한 모든 변경에 대해 누가, 언제, 무엇을, 변경 전·후 값으로 남는다.
- 전용 도구로 저장한 결과가 웹 화면에서 같은 작업을 한 결과와 같다.
